# Raahi — three-minute demo

## 0:00–0:25 — Problem

Mountain maps show where a trail should be, but not whether its information is current. Raahi is an offline-first decision-support layer powered by Exasol.

## 0:25–0:55 — Journey pack

Open My Journey. Explain that the Triund pack contains route evidence and decision rules produced by Exasol. Toggle Offline. Adjust pace, daylight and battery to show Decision Checkpoints still run locally.

## 0:55–1:35 — Offline report

Open Report a Change. Select Bridge damaged, add a short observation and save it. Point out the pending sync queue and unique report ID. Try syncing while offline.

## 1:35–2:10 — Reconnection climax

Toggle Online and synchronize. Explain that REPORT_ID makes retries idempotent. The report enters Exasol, where it is corroborated with active reports and changes segment evidence.

## 2:10–2:40 — Trust Receipt

Open Trust Receipt. Explain the deliberate separation: corroboration increases evidence confidence, while a verified hazard worsens segment condition.

Briefly open Trail Party, show Kabir out of range, and run Spot nearby friends. Explain that regroup information remains offline and that production peer discovery uses consent-based Bluetooth Low Energy.

## 2:40–3:00 — Close

Raahi does not claim a trail is safe. It tells travellers what is known, what changed and what assumptions they should reconsider. “The map shows the trail. Raahi shows what changed.”
